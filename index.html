Profile

Summary

I build the parts of a product that carry the load — the API under an admin panel, the queue that has to drain before morning, and the interface sitting on top of both.

Most of my work has been Persian‑first, which means RTL is not an afterthought in anything I ship: mirrored layouts, Persian numerals, Jalali dates, and collation that behaves in Postgres and MySQL. I have built the same discipline into LTR products for English‑speaking teams.

On the front end I work in React and Next.js with TypeScript. On the back I reach for Laravel or Django depending on what the team already runs, and drop to Go when something has to be fast or hold a lot of connections at once — bulk SMS dispatch, GPS ingestion, WebSocket rooms. I care more about the seams between those pieces than about any one of them.

How I work

Four habits
01

Model the data first

Schema before endpoints, endpoints before screens. Most confusing UI turns out to be a confused data model.

02

Thin, boring slices

Ship the smallest path that works end to end, then widen it. A feature nobody can deploy is not a feature.

03

Pick the dull tool

Laravel or Django unless there is a reason not to; Go when something has to be fast or hold many connections.

04

Leave it runnable

Tests on the parts that break, a README that works on a clean machine, and logs that say what went wrong.
